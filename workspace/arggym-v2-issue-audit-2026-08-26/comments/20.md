Confirmed against the v2 snapshot at `1fdc9db`: the parser has naming rules, but the prompts do not state them.

The shared answer parser requires identifiers to start with an ASCII letter and continue with word characters ([`core/scoring.py:14-16`](https://github.com/ieddeveci/ArgGYM/blob/1fdc9db03ddcc415abd82bef0f230ab31b8a6892/ArgGYM_v2/core/scoring.py#L14-L16)). In a direct probe, `[defeasible _bad: aa0 => bb0]` and `[premise: _bad]` were unparseable, while `good_name` parsed. [`NOTATION.md:22-26`](https://github.com/ieddeveci/ArgGYM/blob/1fdc9db03ddcc415abd82bef0f230ab31b8a6892/ArgGYM_v2/NOTATION.md#L22-L26) says only that rule names and literals are distinct.

Remaining acceptance criterion: state the identifier grammar in every prompt that asks the model to create a rule or premise, ideally with one valid and one invalid example. Alternatively, broaden the parser and define the accepted grammar as part of the DSL specification.
