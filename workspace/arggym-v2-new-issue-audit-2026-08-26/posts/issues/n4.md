## Summary

`claim_chain` asks for a line in premise-to-claim order, but its score ignores order. Reversing the complete gold answer still receives a perfect score.

This was reproduced from owner `main` at `1fdc9db`.

## Evidence

The prompt requires the argumentation line “in order from the premise to the claim” ([`claim_chain.py`](https://github.com/ieddeveci/ArgGYM/blob/1fdc9db03ddcc415abd82bef0f230ab31b8a6892/ArgGYM_v2/tasks/claim_chain.py#L305-L317)). The scorer converts the reference and prediction to sets before computing F1 ([`claim_chain.py`](https://github.com/ieddeveci/ArgGYM/blob/1fdc9db03ddcc415abd82bef0f230ab31b8a6892/ArgGYM_v2/tasks/claim_chain.py#L342-L349)). It computes `correct_order`, but exposes it only as a diagnostic ([`claim_chain.py`](https://github.com/ieddeveci/ArgGYM/blob/1fdc9db03ddcc415abd82bef0f230ab31b8a6892/ArgGYM_v2/tasks/claim_chain.py#L367-L371)).

For the official level-9, seed-0, last-link item, I reversed all 22 reference directives and scored that prediction:

```text
score=1.0
correct_order=False
```

## Impact

The score does not measure the sequencing requirement stated in the prompt. A model can return the right components in an unusable order and receive full credit for tracing the argumentation line.

## Suggested fix

Include sequence correctness in the primary score. Exact sequence matching would enforce the current contract; an edit-distance or LCS component could retain partial credit while ensuring a complete reversal is not perfect.
