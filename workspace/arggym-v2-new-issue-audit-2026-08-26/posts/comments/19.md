A v2-specific negative control adds another parser-contract failure to this issue: rule keywords can be paired with the wrong arrow without losing credit.

Both scoring parsers match either `=>` or `->` but discard which arrow was matched ([`core/scoring.py`](https://github.com/ieddeveci/ArgGYM/blob/1fdc9db03ddcc415abd82bef0f230ab31b8a6892/ArgGYM_v2/core/scoring.py#L15), [`formalization.py`](https://github.com/ieddeveci/ArgGYM/blob/1fdc9db03ddcc415abd82bef0f230ab31b8a6892/ArgGYM_v2/tasks/formalization.py#L359-L385)). The canonical DSL parser correctly rejects:

```text
[defeasible w: aa0 -> bb0]
```

with `defeasible_missing_arrow`, while the scorer parses it as one defeasible rule.

I then changed a gold counter-argument line from `[defeasible w: br0 => -er3]` to `[defeasible w: br0 -> -er3]`. The mutated answer still scored `1.0`; the same keyword/arrow mutation also scored `1.0` in `formalization`.

The acceptance criterion should therefore cover the full documented rule syntax: a strict keyword requires `->`, a defeasible keyword requires `=>`, and malformed pairs must be rejected or penalized.
