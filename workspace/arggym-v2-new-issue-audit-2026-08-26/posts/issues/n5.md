## Summary

`counter_argument` gives every injected language-enrichment rule an `lx_` name while core rules retain `d...` names. This exposes which rules are synthetic noise.

This was reproduced from owner `main` at `1fdc9db`.

## Evidence

The task creates a disconnected enrichment component with the fixed `lx` prefix ([`counter_argument.py`](https://github.com/ieddeveci/ArgGYM/blob/1fdc9db03ddcc415abd82bef0f230ab31b8a6892/ArgGYM_v2/tasks/counter_argument.py#L173-L176)). Although the module imports `randomize_rule_names`, it never calls it ([`counter_argument.py`](https://github.com/ieddeveci/ArgGYM/blob/1fdc9db03ddcc415abd82bef0f230ab31b8a6892/ArgGYM_v2/tasks/counter_argument.py#L12-L13)).

I sampled all eight cells at levels 3 and 6, with both orderings and seeds 0 and 1. In every item:

- filler rules were exactly `lx_901` through `lx_904`;
- core rules used `d...` names;
- no `lx_` rule appeared in the reference answer.

## Impact

A solver can discard every injected enrichment rule from its name alone. The added component therefore increases prompt length without measuring whether the model can identify graph relevance.

## Suggested fix

Randomize rule names after enrichment is appended, then remap every stored rule reference used for candidates and gold generation. Add a leakage check that the name distribution does not predict component membership.
