## Summary

`preference_construction` contains a shared-conflict branch intended to let one
preference directive affect multiple goals. Its level condition is false at
every level in the official v2 grid, so the benchmark never exercises that
feature.

This was reproduced from owner `main` at `1fdc9db`.

## Evidence

[`build`](https://github.com/ieddeveci/ArgGYM/blob/1fdc9db03ddcc415abd82bef0f230ab31b8a6892/ArgGYM_v2/tasks/preference_construction.py#L91-L104)
enables the branch only when:

```python
shared = level >= 5 and (level % 3 == 2)
```

That condition is true at levels 5, 8, 11, and 14. V2 evaluates levels 3, 6,
9, 12, and 15:

```text
L3=False  L6=False  L9=False  L12=False  L15=False
```

A scan of the frozen v2 pilot taskset independently found
`shared_conflict=False` in all 200 `preference_construction` items.

## Impact

An implemented structural feature has zero coverage in the benchmark's actual
level grid. In particular, official cells cannot test whether a model avoids
redundant directives when one preference can settle more than one goal.

This does not imply that every correct answer is automatically minimal; other
generator structures can also make the exact minimum smaller than the goal
count. The defect is the dead feature and the missing coverage.

## Suggested fix

Define the shared-conflict schedule over the levels that v2 evaluates, rather
than over unreachable intermediate levels. Add a regression test that generates
the official grid and asserts that the intended shared cases occur at their
scheduled levels.
