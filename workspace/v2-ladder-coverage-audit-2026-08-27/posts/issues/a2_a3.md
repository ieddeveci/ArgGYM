## Summary

The `defence` difficulty schedule has two related defects: L12 and L15 use the
same structural recipe, while the L6-to-L9 step changes attacker count,
strictness, both chain depths, and strict-rule decoys together.

These have one cause and one remedy, so they are reported together.

This was reproduced from owner `main` at `1fdc9db`.

## Evidence

[`build_defence_item`](https://github.com/ieddeveci/ArgGYM/blob/1fdc9db03ddcc415abd82bef0f230ab31b8a6892/ArgGYM_v2/tasks/attack_defense.py#L256-L275)
derives the structural parameters from adjacent arithmetic schedules, several
of which cap at 5.

Generating seed 0 at the official last-link levels gives the following metadata
tuple:

```text
(attackers, strict attackers, support depth, attacker depth, decoys, strict-rule decoys)

L3   (2, 0, 2, 2, 0, 0)
L6   (3, 0, 3, 3, 1, 1)
L9   (4, 1, 4, 4, 1, 2)
L12  (5, 1, 5, 5, 2, 3)
L15  (5, 1, 5, 5, 2, 3)
```

Reproduction:

```bash
cd ArgGYM_v2
python - <<'PY'
from tasks import attack_defense as ad

keys = (
    "n_attackers", "n_strict_attackers", "support_depth",
    "attacker_depth", "n_decoys", "n_decoy_strict",
)
for level in (3, 6, 9, 12, 15):
    item = ad.make_item(level, 0, "last_link_elitist", mode=ad.DEFENCE)
    print(level, tuple(item.metadata[key] for key in keys))
PY
```

## Impact

L12 and L15 measure the same nominal difficulty recipe, so the top comparison
does not test a harder structure. The L6-to-L9 comparison is confounded in the
opposite direction: it introduces a new attacker type and more of several
existing dimensions at once. Model-score changes across these steps cannot be
cleanly interpreted as a gradual difficulty response.

## Suggested fix

Use an explicit schedule for the official levels. Ensure each rung has a
distinct recipe, and introduce strict attackers on a step that does not also
increase attacker count and both depths. Add regression tests for recipe
uniqueness and for the intended per-step changes.
